AWS shipped a new AgentCore Runtime (announced 18 Sep), and the interesting part isn't a feature. It's two changes to how a session's compute gets handled.

First, memory. Before, memory was held until the session ended, so you paid for the peak. Now each session starts with a small memory profile, grows on demand, and hands memory back when it's no longer used. Billing follows actual usage.

Second, cold starts. The runtime prepares the agent environment once and snapshots it. Every new instance restores from that snapshot instead of repeating the full startup sequence. AWS reports a P75 cold start of 1.9 to 2.0 seconds for container images from 200 MB to 2 GB. V1 was 5.4 to 30 seconds.

That's AWS's own testing, not mine. I'd treat it as a vendor benchmark until my own image has been through it.

What I'd check first: if you slimmed your agent image to dodge cold starts, that work may matter less now, because start time no longer tracks image size. Re-measure before you undo anything.

To try it, set platformVersion to V2 when you create or update a runtime. It's live in us-east-1, us-east-2, us-west-2, eu-west-1 and ap-northeast-1.
